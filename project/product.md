# Moukie

**Nature** : open source

Le site de documentation web du plugin Claude Code Moukie, mis en ligne publiquement. Il vit dans le dépôt du plugin, qui est la matière qu'il décrit.

## Problème
Un développeur qui découvre Moukie n'a qu'un README : daté (ancien nom, ancien pipeline), sans design, sans vue d'ensemble. Il ne comprend ni ce que fait Moukie, ni en quoi il diffère des autres workflows spec-driven, comme Superpowers ou Spec Kit. Le mainteneur, lui, n'a aucune vue fidèle de l'état du plugin au fil des versions.

## Cible
- **Cœur de cible** : les développeurs solo qui utilisent déjà Claude Code et veulent livrer seuls une app front et back, de la maquette à la PR.
- **Lecteur secondaire** : le mainteneur du plugin, qui s'en sert pour garder une vision claire de Moukie.

## Proposition de valeur
Comprendre Moukie en quelques minutes et l'installer, sur une documentation qui reflète toujours la version courante du plugin.

Message porté par le site : « Seul, de la maquette Figma à la PR : Moukie code ton front et ton back en parallèle contre un contrat partagé. »

## Périmètre
- Dans le périmètre :
  - Accueil : le positionnement et l'appel à démarrer
  - Getting started : la présentation, les prérequis, l'installation
  - Skills : la référence de chaque skill du plugin
  - Agents : la référence de chaque agent du plugin
  - Workflow map : l'enchaînement complet du workflow
  - Le site en français et en anglais, avec un sélecteur de langue
  - Un lien vers le dépôt GitHub
  - La mise en ligne publique
- Hors périmètre : la recherche, la doc versionnée par version du plugin, le changelog, un exemple de bout en bout, les pages pour contributeurs, la mesure d'audience.

## Critères de succès
- Plus d'installations du plugin, sans mesure chiffrée.
- À chaque nouvelle version du plugin, la doc en ligne est à jour sans qu'on réécrive la référence à la main.
